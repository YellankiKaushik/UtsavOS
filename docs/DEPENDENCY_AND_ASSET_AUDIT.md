## Dependency maintenance and repository security

- **Vulnerabilities.** `npm audit --json` exited 1 with eight moderate package findings in the linting chain around `eslint-config-next`, TypeScript ESLint and `minimatch`. The production-only command, `npm audit --omit=dev --json`, exited 0 with zero reported findings. These are registry results for this snapshot. Review the underlying advisories and compatible fixes in a focused PR. npm offered a major change to `eslint-config-next` for some paths, so do not apply `npm audit fix --force` as routine maintenance.
- **Actions.** The workflow uses read-only repository permissions and ordinary `pull_request` checks. Checkout, setup-node and upload-artifact use moving `@v4` tags. In a focused follow-up, pin each to a verified upstream commit SHA and keep the version in a comment. Keep the existing required check names. [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use)
- **Dependency updates.** There is no tracked Dependabot or Renovate configuration. GitHub's alerts settings endpoint returned 404 with the available credentials, so repository alert status is unverified. Confirm it in repository settings, then consider reviewed weekly npm and Actions updates without automatic merges.
- **Vulnerability intake.** The authenticated GitHub endpoint confirmed private vulnerability reporting is enabled. Use the repository's Advisories page and identify a maintainer to monitor reports. [GitHub private reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)
- **Secrets.** Git ignores local environment files and private runtime artifacts. The staged-value, reachable-history and built-client scans have different scopes. The repository history script checks selected provider formats and configured values. Before a release, use a redacted scanner that also covers GitHub tokens and private keys, verify scan coverage on the release refs, and keep findings out of public artifacts. Check GitHub push protection and alert routing with the maintainer.

Owner decisions are to confirm the distribution scope and license, assign responsibility for notices and vulnerability reports, and approve any GitHub security settings or automated update policy in a separate change.
