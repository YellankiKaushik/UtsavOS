## Static showcase distribution

`showcase/dist` contains standalone HTML, CSS and JavaScript plus the MIT license and generated `THIRD_PARTY_NOTICES.txt`. Its Vite build fails if an import falls outside the audited browser module allowlist (React, React DOM, Scheduler and Zod); the build emits notices only for packages found in the actual browser bundle. Vite and the original app's broader dependency graph are build or self-hosting requirements, not showcase runtime requests. The offline Playwright suite blocks traffic outside the generated same-origin files. It does not make a claim about every possible server distribution of the full Next.js application.

The showcase uses system fonts, invented event fixtures and original inline SVG paths. It does not include the historical production screenshots, Lucide package, Supabase client, Next.js routes or AI adapters. The full-stack application and any server/container distribution need their own artifact-specific license and notice review.

## Dependency maintenance and repository security

- **Vulnerabilities.** On 8 November 2026, `npm audit --json` reported eight moderate findings in the development lint chain. The root finding is `minimatch`'s globparts-amplification denial of service ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)); the reported affected range is `>=7.0.0 <11.0.1`. The production-only command, `npm audit --omit=dev --json`, exited 0 with zero reported findings. npm offered `eslint-config-next@15.5.29` as a semver-major fix path from this Next 16 tree. No breaking downgrade or incompatible override was applied. Recheck the advisory and compatible fixes in a focused dependency PR; the current lint tooling does not parse user-supplied glob patterns at runtime.
- **Actions.** Checkout v7.0.1, setup-node v7.1.0 and upload-artifact v6.0.0 (Node 24) are pinned to verified upstream commit SHAs. The workflow uses read-only repository permissions, `pull_request` checks and `persist-credentials: false`. Hosted Linux runners provide the required action runtime; recheck self-hosted runner requirements before using them. Keep existing required check names and review pin updates. [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use)
- **Dependency updates.** `.github/dependabot.yml` requests weekly npm and Actions updates and excludes npm major version bumps from automatic update PRs. Review update PRs before merging; do not use force upgrades merely to quiet a report. GitHub's alerts settings endpoint returned 404 with the available credentials, so repository alert status is unverified. Confirm it in repository settings.
- **Vulnerability intake.** The authenticated GitHub endpoint confirmed private vulnerability reporting is enabled. Use the repository's Advisories page and identify a maintainer to monitor reports. [GitHub private reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)
- **Secrets.** Git ignores local environment files and private runtime artifacts. The staged-value, reachable-history and built-client scans have different scopes. The repository history script checks selected provider formats and configured values. Before a release, use a redacted scanner that also covers GitHub tokens and private keys, verify scan coverage on the release refs, and keep findings out of public artifacts. Check GitHub push protection and alert routing with the maintainer.
