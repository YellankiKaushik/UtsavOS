# Billing foundation — disabled test mode

Implemented independently of provider account setup: domain subscription states, exact raw-body verifier boundary, parameterized worker adapter, durable receipts, binding authorization, subscription-scoped worker leases, epoch conflict rejection, five-attempt retry/dead-letter handling and short-lived entitlements. No price catalog entry or customer binding is seeded in hosted staging. The public webhook remains503 and no checkout control is exposed.

Code: src/domain/billing.ts, src/application/billing.ts, src/infrastructure/billing-store.ts; migration20261029112216_billing_reconciliation_foundation.sql. Tables/functions live in private schema with RLS/revoked anon/authenticated privileges. Only a separately approved worker principal may enqueue/reconcile. Ordinary web sessions never receive a service-role secret.

Delivery contract: retain exact bounded raw bytes; invoke the official SDK signature/freshness verifier before parsing; normalize only a test-mode event ID and subscription ID; durably deduplicate by ID and payload digest. The injected verifier is an interface, not a claim of successful Stripe signature verification. Tests use explicit verifier doubles. Incoming metadata cannot bind a workspace, choose a commercial plan or directly set access.

Claim a durable receipt under the subscription row lock before retrieving the authoritative current subscription. Old/new event delivery order therefore triggers reconciliation, not timestamp-based state rollback. Completion requires the matching unexpired UUID lease and monotonically increasing worker epoch. Customer/subscription IDs and a trusted operator-configured price must match. Active/trialing snapshots with a future period end grant bounded catalog limits until the earlier of period end or24hours; other statuses suspend the paid entitlement and preserve records. The existing pilot fallback policy is unchanged. Reconcile periodically before expiry after a worker is genuinely deployed.

Retry failures with allowlisted codes, exponential backoff and at most five claims. Expired leases can be recovered; an old worker cannot complete a newer claim. Dead-letter review/replay must be operator-authorized. Scheduled reconciliation can enqueue a distinct operator-generated event ID through the same path; no scheduling service is currently activated.

Verification:6 integration cases and an independent native PostgreSQL race test. Real Stripe account/customer/subscription events, official SDK signature verification, a deployed worker/scheduler, checkout, price approval and payment tests remain unverified. Do not enable billing from a feature flag alone.
